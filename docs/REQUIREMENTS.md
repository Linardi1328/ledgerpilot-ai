# Functional Requirements

Functional requirements are stable identifiers for planned product capability. Phase 0 documents these requirements; it does not implement application functionality.

| ID | Title | Actor | Priority | Scope | Preconditions | Expected result | Controls | Acceptance evidence | Description |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| FR-001 | Workspace management | Firm Administrator | Must | MVP | Administrator is authenticated and authorised | Firm workspace can be configured | RBAC; audit event | Workspace settings test and audit log | Manage firm-level settings without bypassing accounting controls. |
| FR-002 | Role assignment | Firm Administrator | Must | MVP | User exists in firm tenant | Role is assigned or removed | Least privilege; audit event | Role assignment test | Assign roles while preserving separation between administration and accounting approval. |
| FR-003 | Client isolation | All authorised users | Must | MVP | User is scoped to tenant/client | User only sees authorised client data | Tenant/client ownership checks | Cross-client access tests | Prevent authorised application paths from leaking data across firms or clients. |
| FR-004 | Document submission | Client / Submitter, Accountant | Must | MVP | User can upload for client | Document record is created | File policy; tenant scope | Upload test with synthetic file | Accept supporting documents for authorised client entities. |
| FR-005 | File validation | System | Must | MVP | Document submitted | Invalid files are rejected or quarantined | Type allowlist; size limit; malware scan | File validation tests | Validate uploads before storage or extraction. |
| FR-006 | Document storage | System | Must | MVP | File passes validation | Original file is stored with metadata | Controlled storage; signed access | Storage metadata test | Preserve source evidence and metadata for later traceability. |
| FR-007 | Structured manual input | Accountant | Must | MVP | Synthetic purchase invoice is available | Structured invoice fields can be entered | Required-field validation | Manual input workflow test | Support manual structured input before OCR is implemented. |
| FR-008 | Extraction run recording | System | Should | Future | Extraction provider is configured | Extraction run and provider metadata are recorded | Provider boundary; version tracking | Extraction-run persistence test | Track future OCR/AI extraction attempts and outputs. |
| FR-009 | Field validation | System | Must | MVP | Structured fields exist | Missing or invalid fields are flagged | Deterministic validation | Validation test | Validate required invoice fields before recommendation. |
| FR-010 | Arithmetic validation | System | Must | MVP | Invoice totals and lines exist | Arithmetic mismatches block approval | Decimal arithmetic; deterministic rules | Arithmetic test | Validate line totals, taxes, subtotals, and grand total. |
| FR-011 | Duplicate detection | System, Accountant | Must | MVP | Invoice identifiers or fingerprints exist | Possible duplicates are flagged with explanation | Explainable warning; reviewer decision | Duplicate-detection test | Identify potential duplicate documents or invoices before approval. |
| FR-012 | Supplier/customer matching | System, Accountant | Must | MVP | Counterparty data exists | Candidate supplier/customer matches are suggested | Confidence; reviewer confirmation | Matching test | Suggest matches while allowing human correction. |
| FR-013 | Coding recommendation | System | Must | MVP | Validated invoice and rules exist | GL account/category suggestion is produced | Rule version; explanation; confidence | Recommendation test | Recommend accounting coding using configurable rules and provider-independent logic. |
| FR-014 | Tax-code recommendation interface | System, Accountant | Should | MVP | Tax configuration exists | Tax-code recommendation is displayed for review | Expert validation required | Interface/contract test | Provide a reviewable tax-code recommendation interface without unsupervised tax advice. |
| FR-015 | Cost-centre recommendation interface | System, Accountant | Should | MVP | Cost-centre configuration exists | Cost-centre suggestion is displayed for review | Rule version; reviewer confirmation | Interface/contract test | Support optional cost-centre recommendations. |
| FR-016 | Journal generation | System | Must | MVP | Validated invoice and coding exist | Balanced draft journal is suggested | Total debits equal credits | Journal-balance test | Create a reviewable double-entry journal suggestion. |
| FR-017 | Confidence and risk indicators | System | Must | MVP | Recommendation package exists | Confidence and risks are visible to reviewer | No hidden uncertainty | Review UI/API test | Show uncertainty, duplicate risk, policy exceptions, and validation status. |
| FR-018 | Review routing | System | Must | MVP | Risk and authority rules exist | Work is routed to accountant or senior reviewer | Configurable thresholds; audit event | Routing test | Route ordinary, high-risk, high-value, and exception work appropriately. |
| FR-019 | Accountant approval | Accountant | Must | MVP | Transaction is ordinary and controls pass | Transaction is approved within authority | RBAC; journal balance; audit event | Approval test | Allow delegated approval without bypassing controls. |
| FR-020 | Senior approval | Senior Reviewer | Must | MVP | Work requires senior review | Sensitive or high-risk transaction is approved or rejected | Authority; comment; audit event | Senior approval test | Require senior review for high-risk or exceptional items. |
| FR-021 | Correction before approval | Accountant, Senior Reviewer | Must | MVP | Work is not approved | Corrected fields and recommendations are revalidated | History retained; revalidation | Correction test | Allow reviewer correction while preserving what changed and why. |
| FR-022 | Correct approved records | Senior Reviewer, controlled workflow | Should | Future | Record is approved/exported | Correction uses reversal or supersession | No silent overwrite | Reversal/supersession test | Preserve approved history while correcting accounting outcomes. |
| FR-023 | Rejection | Accountant, Senior Reviewer | Must | MVP | Work is reviewable | Work is rejected with reason | Reason required; audit event | Rejection test | Reject invalid, duplicate, unsupported, or inappropriate work. |
| FR-024 | Escalation | Accountant, System | Must | MVP | Review uncertainty or threshold exists | Task moves to senior review | Reason required; audit event | Escalation test | Escalate exceptions and unusual items. |
| FR-025 | Information requests | Accountant, Senior Reviewer, Submitter | Must | MVP | Required information is missing | Request is sent and response is tracked | Tenant/client scope; audit event | Information-request test | Ask submitters for missing or unclear information. |
| FR-026 | Audit history | All authorised viewers | Must | MVP | Auditable action occurs | Event is recorded and queryable | Append-only design; redaction | Audit-event tests | Preserve attributable history for documents, recommendations, decisions, and exports. |
| FR-027 | Rule configuration | Firm Administrator | Should | MVP | User has configuration permission | Accounting rules can be configured and versioned | Versioning; audit event | Rule-version test | Configure and version firm/client accounting rules. |
| FR-028 | Provider configuration | Firm Administrator | Should | Future | Provider credentials exist securely | Providers are configured through abstractions | Secret management; audit event | Provider-config test | Configure OCR, AI, storage, MyInvois, and accounting gateways without coupling core logic. |
| FR-029 | Version tracking | System | Must | MVP | Rules/models/providers produce output | Rule/model/provider versions are retained | Recommendation lineage | Version-lineage test | Track the inputs behind recommendations and decisions. |
| FR-030 | Reconciliation support | Accountant | Could | Future | Bank transaction data exists | Candidate reconciliation matches are suggested | Reviewer approval; audit event | Reconciliation test | Support future bank reconciliation workflows. |
| FR-031 | Export approved entries | Accountant, Senior Reviewer, Integration worker | Should | Future | Transaction is approved | Entry is exported idempotently | Idempotency; duplicate prevention | Export idempotency test | Export only approved entries to provider-independent accounting gateways. |

## Notes

- MVP and Future labels define target timing, not implementation status.
- Tax-related requirements are not tax advice and require independent expert validation.
- All examples and tests must use synthetic data.
